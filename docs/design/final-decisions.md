# 最终决策补充（覆盖 vfs-format.md 中冲突的部分）

用户确认：controversies.md 的 35 条全部采纳（第 24 条旧 pack 格式被新 .vfs 格式取代；第 29 条保留 NS_VFS_BEGIN/NS_VFS_END 宏，接口名 IFileStream）。
vfs-format.md 的大部分设计保留，但按“快速高效、简单为主”做以下简化，冲突时以本文件为准：

1. 版本兼容：只存一个格式版本号，不一致直接拒绝。不做 major/minor、不做特性位。
2. 损坏检测：只校验 Header 与索引区（XXH3-64 或 CRC32），用于快速判断文件是否损坏。不做 header 认证、不做 Ed25519 签名，移除 Monocypher 依赖。
3. 单文件哈希：打包时写入索引（XXH3），运行时默认不校验；仅 `vfstool verify` 离线检查使用。
4. 单文件加密：多字节 XOR。每个文件在索引中存 16~32 字节 key，按 (文件内偏移 % keyLen) 异或，支持随机 seek。索引中每文件有加密方式字段（NONE / XOR，预留扩展）。
5. 索引区加密：ChaCha20（项目内自带实现，约百行，用 RFC 8439 测试向量在 doctest 中验证），不引入额外第三方库。密钥直接存放在 vfs 文件里即可（不追求高安全性），也允许运行时/CLI 传入覆盖。
6. 压缩：支持按单文件可选的 LZ4 压缩，默认关闭；压缩文件打开时整体解压到内存（不能按偏移流式读）。由打包时 glob 规则决定（建议用于配置/脚本/文本等小文件）。顺序：先压缩再加密。
7. 空目录：默认不保留空目录（可选参数开启）。
8. 可复现：同一目录每次打包输出逐字节一致：路径排序、mtime 默认写 0、每文件 XOR key 与索引 nonce 由内容/路径确定性派生（不随机）。
9. 对齐：默认 16 字节对齐（可配置，含 1 = 不对齐）。
10. 去重：内容完全相同的文件只存一份数据，多个索引条目指向同一偏移。
11. 第三方依赖仅：doctest、xxHash、LZ4、CLI11（命令行），全部放 3rd/。
12. 运行时归档只读；新 VirtualFileSystem 完全移除旧 pack 支持。
13. 一切以读取速度为先。
